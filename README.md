# Olist Marketplace Investigation

## Business problem
Marketplace revenue depends heavily on first-time buyers. The goal of this project is to understand why customers buy once and never return, and how much revenue is at risk because of late deliveries.

## Core questions
- How did monthly revenue and order volume trend over time?
- Which categories and states drove the most revenue?
- What share of customers purchased more than once?
- How much of the order volume arrived late?
- Did late orders receive lower review scores?
- Were customers whose first order was late less likely to return?

## Important data caveat
customer_id is unique per order, not per customer. For retention analysis, use customer_unique_id. Otherwise repeat-purchase rate will be artificially low.

## Dataset
Brazilian E-Commerce Public Dataset by Olist (Kaggle)

## Tech stack
- MySQL for SQL analysis
- Python + pandas for cleaning and exploratory analysis
- Power BI for analysis dashboard
- GitHub for project documentation and repo hosting

## Project structure
- sql/: SQL scripts for schema, quality checks, revenue, retention, delivery, reviews, RFM, and view creation
- notebooks/: Python analysis notebook
- data/raw/: raw Olist CSV files
- data/cleaned/: cleaned export files for reporting
- powerbi/: Power BI dashboard files and screenshots
- docs/: README and findings memo

## Key findings
- Late orders are associated with lower review scores
- A significant share of revenue is connected to delayed deliveries
- Repeat purchase behavior is concentrated in a subset of customer groups
- A limited number of states and sellers drive a disproportionate share of late delivery risk

## Reproduction steps
1. Download the Olist dataset from Kaggle.
2. Place the CSV files in `data/raw/`.
3. Run the SQL scripts in this order:
   - `sql/01_schema.sql`
   - `sql/02_data_quality.sql`
   - `sql/03_revenue.sql`
   - `sql/04_retention.sql`
   - `sql/05_delivery.sql`
   - `sql/06_reviews.sql`
   - `sql/07_rfm.sql`
   - `sql/08_views.sql`
4. Open the notebook in `notebooks/analysis.ipynb`.
5. Export cleaned files for Power BI.
6. Build the dashboard in `powerbi/olist_marketplace.pbix`.

## Assumptions and limitations
- This project analyzes public marketplace data rather than live operational metrics
- It focuses on historical correlations, not strict causality
- Review data is incomplete for some orders
- Delivered orders are the primary basis for late-delivery analysis

## DAX dictionary
- Revenue = total order value
- Orders = distinct count of order IDs
- AOV = revenue divided by orders
- Late % = percentage of delivered orders that were late
- Revenue MoM % = month-over-month revenue change
- Repeat Customers % = share of unique customers with more than one order
- Revenue at Risk = revenue generated by late orders
